# TiPE 白话说明

TiPE 会在你输入时记住必要的按键、候选选择和最终提交结果。记录先放在本机的有界队列里，后台慢慢整理，所以输入时不会等待模型或网络。

控制中心提供暂停/恢复、关闭/开启学习、清空本地记录和导出记录。导出在后台运行，按钮会变成“取消导出”；取消时保留原来的完整文件。重复打开控制中心会唤起已有窗口。关闭学习后输入仍然正常；重新开启后才会恢复观察。清空会删除个人词偏好和事件计数。云端增强默认关闭，只有配置服务并明确同意后才会在后台运行，界面会显示发送和重试状态。

从应用菜单打开 TiPE，或运行 `tipe-control`，即可进入深色控制中心。“学习状态”页分别显示运行状态、观察次数、已学词与模式以及当前模型；常用操作按用途分组。窗口变窄或字体放大时，卡片会自动换行，页面可以纵向滚动。

密码或标记为敏感的输入框不会进入学习。数据默认保存在 `$XDG_STATE_HOME/tipe`，未设置时为 `~/.local/state/tipe`；模型发布保留上一版，可从控制中心回滚。

Wine 使用的 XIM 协议不能可靠识别密码框，因此该路径默认不学习，中文输入仍可使用。原生 Wayland 应用刚切换字段、尚未说明输入用途时，会暂时直接输入原文并停止学习；用途到达后自动恢复。若应用一直不提供用途，会保持这个保护性回退，并记录诊断原因。

控制中心的“模型”页提供三种选择：

- **TiP**：默认选项，从明确选词、修改和重复输入中学习个人习惯。
- **本地小模型**：在本机学习反复确认的汉字搭配，辅助排序后面的候选。基础词库的首选受到保护，不需要手动更新模型。
- **云端大模型**：可选增强，需先配置服务并明确同意。只发送必要的拼写、确认结果、匿名场景标识和时间间隔，不发送原始按键流、密码或整段周围文本。返回结果只临时补充到候选中，不改基础词库。

API Key 只从你指定的私有文件读取。在“模型”页展开“云端与文件设置”，可保存密钥文件位置并查看运行详情。默认不会联网。服务的详细配置见 [云端说明](CLOUD-TRANSPORT.zh-CN.md)。

“支持”页提供项目所有者的微信和支付宝收款码。图片随程序打包，离线也能显示；卡片展示二维码区域，点击“查看收款码原图”可打开包含平台和收款人信息的完整图片。窗口较窄或系统字体较大时，两张卡片会自动改为上下排列并可滚动查看。

基础词库与个人学习分开保存。明确选过的词可以逐渐排到前面，重复三次以上的精确个人词才会对同一拼音和场景加入候选，不会改写基础词库。纠错可学习漏字、多字、替换和相邻字母颠倒，按竞争证据计算置信度；同一场景至少需要 6 次支持和 3 种修正拼音，只在 LibIME 仅返回原文时介入，并且不会把推断候选反过来当作训练证据。其他拼音不会受到这条个人词或规则影响。学习文件使用临时文件和原子替换，更新失败会保留上一版。

黑色候选条默认是一行，按 ↓ 或 Tab 展开。展开保留原来的列数、列宽和窗口宽度，增加候选行；靠近屏幕底部时，窗口可以向上避让。长候选按实际文字宽度排版。

拼音光标在末尾时，右方向键移到下一个候选，保持单行；左方向键先向前移动候选，回到首项后再返回拼音编辑。超过当前一行或编号页时，候选条会滚动显示高亮项，不会自动展开。单行状态下，按 Home / End 可直接定位拼音光标，左右键继续编辑；光标移到拼音末尾后，再按右键进入候选。Shift+Tab 收起网格后仍保留高亮选择，空格提交该项，Enter 始终提交原文。

数字 1–9 和 0 选择当前显示编号的一组候选，PageUp/PageDown 翻页。拼音有独立编辑光标；左右、Home/End 移动，Backspace/Delete 删除光标处的字母，继续输入会插入当前位置。

很长的拼音也可以继续选中文。TiPE 会先处理前面一段；选好后，后面的拼音
仍留在输入框里，可以继续选择、修改或按 Enter 提交原文。中英切换会保留
整个未完成组合。

候选窗通过应用提供的文本光标位置定位。GTK、Qt 和原生 Wayland 输入共用同一套绘制逻辑。Wine 默认 XIM 样式可能只给初始坐标；可使用 [Wine 按应用配置](WINE.zh-CN.md) 启用其标准光标跟随模式，并随时恢复。TiPE 不会猜 niri 窗口坐标。详情见 [协议与回退说明](FCITX-WAYLAND-ADAPTER.zh-CN.md)。

## 开发者命令

`tipe-demo` 可在终端演示拼音、空格、数字选词、方向键和 Shift 中英切换；`tipe-diagnose` 输出热路径采样，`tipe-diagnose --trained-local --representative` 测量已训练本地小模型的普通句子、长组合、编辑和候选导航；`scripts/install-preview.sh` 和 `scripts/uninstall-preview.sh` 只操作 staging 目录。

首次使用：运行 `scripts/install-user.sh` 安装到当前用户，再运行 `scripts/activate-user.sh`。这个脚本会按“停止旧 daemon、写入 profile、只启动一个带 TiPE 路径的 fcitx5、确认当前输入法为 tipe”的顺序执行，避免旧 daemon 把新 profile 覆盖。它不会改 niri 配置。`scripts/enable-user.sh` 和 `scripts/disable-user.sh` 是停 daemon 后使用的底层 profile 编辑命令；检测到 fcitx5 正在运行时会拒绝执行，防止静默丢配置。

安装器也会保存 Fcitx 用户服务专用的 TiPE 加载路径，使用现有 `fcitx5.service`
的桌面在下次登录后仍会加载 TiPE。它不改服务的启动命令、不额外启动一个输入法
进程；没有该服务的桌面使用 `scripts/run-user-fcitx.sh` 启动。卸载会移除或恢复
这份配置。安装本身不会重启正在使用的输入法。

卸载先用 `scripts/uninstall-user.sh --dry-run` 查看清单，再运行 `scripts/uninstall-user.sh`。卸载会从运行中的 Fcitx 各输入法组移除 TiPE，其他输入法保留；文件按安装时的校验记录移除或恢复。你后来改过的文件和原备份会保留，脚本会报告尚未清理的冲突。学习数据、导出文件和 profile 备份默认保留；要清空学习，可在卸载前使用控制中心的“清空”。

安装采用临时目录预演和原子替换，不会原地截断运行中的动态库；文件写入失败或进程中断后可恢复。清单与安装前的文件备份位于 `$XDG_STATE_HOME/tipe/installation`（默认 `~/.local/state/tipe/installation`）。缺少清单的旧安装不会被猜测删除，应先通过当前安装器建立清单。GTK/Qt 可选模块也有独立清单，支持 `scripts/install-client-ui.sh --uninstall`，整个 TiPE 卸载时会一并处理。

中文组合中，空格用于选择当前候选；Enter 保留并提交原始拼音或英文。轻按 Shift 是 TiPE 内部中英切换，未完成的拼音会保留；切换到其他 Fcitx 输入法时，未完成组合会以原文提交，避免凭空消失。若前端提供 client preedit，挂起拼音会继续显示在编辑框内，否则显示在输入面板中。

切换应用时，GTK、Qt 和提供失焦提交的前端会在原输入框提交一次原文。原生 Wayland 终端没有有效周围文本时，TiPE 会暂存组合，返回同一上下文后恢复，避免终端在失焦时清掉未完成拼音。是否暂存由协议与能力标志决定，不按软件名称写分支；进入密码字段或其他输入法时会清理暂存状态。组合不会转移到另一应用。

维护离线语义样本时，可使用 `tipe-trainer --state-dir DIR --input FILE` 批量整理 `拼音<TAB>词<TAB>上下文` 文件。它复用输入法的有界后台学习器，支持暂停和可选回滚；普通输入不需要运行这个工具。


2026-10-21 更新：支持周围文本协议的应用中，提交记录先暂存，下一次操作确认 TiPE 自己的短提交仍在光标前时再学习。立即删除或恢复重编的记录会被丢弃；协议无法证明时不猜测。没有周围文本能力的应用仍从明确选词学习，无法证明任意后续编辑的最终结果。反复用 Enter 保留某个拼写会形成同应用的原文偏好，但中文候选仍保留，选择中文会撤销该原文偏好。

原生桌面自动检查入口：scripts/check-browser-desktop.py、scripts/check-foot-desktop.py、scripts/check-wine-desktop.py。它们只向专用测试窗口输入，每个按键都检查焦点。Wayland 虚拟键盘会绕过输入法抓键，所以原生路径使用当前用户有写权限的 evdev 键盘，只写入测试事件，不读取键盘内容。没有此权限时明确中止。
