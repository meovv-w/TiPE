# TiPE 实现与验证说明（2026-10-23）

这是已完成版本的交付说明。用户于2026-10-23明确回复“这两个不用管”，
实体 niri 多屏与 Discord 登录聊天界面不再作为完成条件；这两项仍为未验证。
当前范围的完整记录见 [验收表](ACCEPTANCE.md)。已知协议限制与尚未覆盖的场景单独列出，不能将自动测试通过解释为
所有软件、所有光标位置和所有显示器组合都已验证。

## 组成与输入路径

`include/tipe` 是接口，`src/tipe_core.cpp` 是 C++20 输入状态机。
`src/tipe_fcitx.cpp` 把 Fcitx 的按键、能力、焦点和周围文本转换为核心操作，
再将 preedit、候选和提交结果交给对应前端。核心可以脱离真实桌面测试。

候选查询使用 LibIME 简体词典 `sc.dict` 与 `zh_CN.lm`。基础词典不可用或
损坏时会记录诊断，并退回有界内置词表。个人数据不写入基础词典，
整句质量由独立语料和噪声隔离测试保护。

同一线程的输入上下文共享一份基础词库与语言模型，各自保留独立的LibIME
组合图；不调用LibIME学习接口修改共享基础数据。插件加载时预热，文件身份、
大小与修改时间变化后重新加载，缺失/损坏仍可回退。12个空闲上下文实测由
约395MB降至46MB，后续初始化由约14ms降至0.08–0.15ms；含实际解码和独立
学习器的12上下文回归，预热后额外RSS约9MB。

`candidate_grid`、`candidate_painter` 与客户端适配层共用一套实际字体测量、
单元格位置、高亮和命中逻辑。默认黑色单行，方向键展开后保留列数与宽度，
只增加行；长候选按实际文字宽度占位。数字作用于当前十项组，翻页超过九项
仍可选择。GTK/Qt 在应用内创建原生 popup；原生 Wayland 使用 classicui 的
input-popup；XIM 使用协议矩形，在桥接能力不足时有可诊断的客户窗口回退。
产品不读取 niri 窗口坐标，不轮询光标。

## 键盘行为怎样进入学习

键按下/释放、删除、编辑导航、候选展开/移动/选择、选词前后拼音、
提交与中英文切换都会进入统一语义事件。上下文按低敏标识隔离，事件携带
有界文本和输入间隔；敏感字段不进入学习。队列容量 2048，后台模型最多
4096 条，过载会丢弃学习事件，不丢应用按键。

低优先级 worker 批量去重与合并，处理个人词、选择链、纠错证据和字符搭配。
持久化采用版本、校验和、私有临时文件、fsync 与原子替换，保留上一版并
自动让后续查询读取新版本。失败显示下次自动重试，不弹训练提示、不要求
点击更新、不在按键线程调用网络或进行同步落盘。

支持周围文本的前端只验证 TiPE 自己短提交的精确后缀，确认最终保留后才
学习；立即删除或重编会撤销待确认记录，不保存应用完整段落。
不能证明任意客户端后续编辑时，不猜测最终结果。

## 三种模型与基础质量

- TiP 默认启用，保存明确选择、精确拼写习惯和选择链。个人新词在同一拼音
  与场景中重复确认后进入候选，不替换成熟词库。
- 本地小模型是后台增量生成的字符二元概率模型，辅助低位候选排序，保护
  基础首选与分段边界；它不是神经网络或大模型。
- 云端是默认关闭的后台可选增强。配置服务并明确同意后，只发送最小化的
  提交/选择语义，不发送原始按键流、密码或整段周围文本。超时、取消、退避
  和严格响应缓存与输入线程分离，结果不污染本地基础词库。

漏键、多键、替换和颠倒需要多种样本及竞争证据，只在基础解码很弱时介入，
推断结果不训练自身。英文、命令、网址、大小写由通用识别与个人原文偏好
处理；明确选择中文可以撤销原文习惯。

## 长拼音、编辑与切换

逐字/分段选词会记录完整选择链，已选前缀与剩余拼音独立，候选立即更新。
UTF-8 preedit 有独立编辑光标，支持左右、Home/End、Backspace/Delete 与
中间插入。删除已提交内容的恢复需要周围文本确认，不能删除未确认属于
TiPE 的客户端文字。Enter 提交原拼写，Space 选中文；Shift 短按可暂存组合，
开始真正输入英文时按稳定的原文规则提交。

展开前缀候选时，消耗长度使用LibIME句子图的真实终点；请求光标落在音节内
不会制造虚假的较短边界。原生Wayland将组合替换与零长度周围删除放在同一
协议事务中，同步客户端的组合范围，避免删空后缀后恢复时重复原字。

超过64字节的组合保留完整原始拼写，解码前70字节作为有界窗口，在64字节内
的完整词边界提供候选；提交后再解码剩余部分。不会在窗口中间制造半个音节
的消耗边界。中间编辑保留解码器未变化的后缀，不再删掉整个后段重新输入。
65/70/100/260字符组合以及编辑后与全新解码逐项一致的回归均已通过。

GTK/Qt 的失焦提交只执行一次。原生终端无法证明保留文本且不提交失焦
preedit 时，TiPE 暂存同一上下文的组合，回来后恢复，进入敏感字段则清理。
原生与 XIM 切窗会隐藏旧候选，不把组合转移给另一个应用。

## 安装、管理与数据

构建和桌面集成方法见 [README](../README.md) 与 [原生集成](../integration/README.md)。
`install-user.sh` 先 staging 再原子替换，安装清单、原文件备份和持久事务
日志位于状态目录的 `installation`。`activate-user.sh` 是实际启用/重启入口，
检查 D-Bus owner 与模块 inode，不能仅凭环境变量认为新版已加载。

本次登录后的最终复核发现临时 manager 环境没有延续，现安装器会事务性保存
`fcitx5.service.d/60-tipe.conf`，只为现有 Fcitx 用户服务配置模块路径和候选样式。
安装/卸载重载服务定义，不自动重启。真实直接重启已证明不依赖临时环境也能
加载三个已测试模块，哈希完全相同；在线加入 TiPE 后成功选中，并恢复用户
原来选择的拼音。证据为 `startup-service-results.json`，安装/卸载及启动回归
见 `ctest-startup-final.log`。不修改 niri 或服务的启动命令。

`uninstall-user.sh --dry-run` 先查看操作；实际卸载在线移除各组 TiPE，保留
其他输入法，再按清单删除或恢复文件。用户后续修改的文件与备份保留并
报告冲突。默认保留个人学习、导出和 profile 备份。真实卸载已在隔离 HOME
测试；当前桌面没有执行卸载。

`tipe-control` 只有“学习状态”“模型”“支持”三页，可暂停/恢复、关闭/开启、
清空、导出和回滚。导出在后台运行，可取消，目标文件保持原子完整。
“支持”页已加入所有者提供的微信/支付宝原图，离线显示并可查看大图，新增4项UI回归通过；当前用户控制中心已更新。
同一窗口重复打开会唤起已有实例。用户操作说明见 [白话说明](USER_GUIDE.zh-CN.md)。

## 当前验证

前一轮长组合/共享词库证据目录为`docs/evidence/2026-10-23`。5000次单键p95
为0.726ms（TiP）与0.761ms（已训练本地模型）；代表性68字节组合逐键p95
为4.20/4.11ms，242字节组合为3.92/3.81ms。所有首轮和最大值均保留，
当时部分中间编辑p95仍有约6–9ms，后续优化结果如下。

随后优化保持LibIME空历史插值的原始浮点评分，省去空表查询和重复的标量计算，
使用2KiB有界精确位键缓存；不缩减30条整句候选或搜索宽度。70组拼写的完整候选、
35,664次逐词浮点评分与原始LibIME相同（仅允许原生完全同分组内部的次序互换）。
展开前缀改用集合去重，连续导航复用同一输入/同一基础列表的结果；个人模型自动
发布和清空后的排序变化会使复用失效，重置与敏感字段切换清理上下文缓存。

最后串行采样中：5000单键p95为0.394ms（TiP）、0.436ms（本地小模型）；
242字节中间编辑p95为4.135/4.067ms，不同长拼写导航p95为1.231/1.234ms。

## 限制与未取得的证据

XIM 不提供可靠敏感字段标志，因此默认关闭全部 XIM 的观察、个人学习和
云端工作，保留中文输入。Wine 默认 XIM spot 可能恒为初始坐标；现提供
可恢复的按应用 `overthespot` 配置，已验证实际 Win32 caret 的横向移动与换行、
六项输入和19项编辑检查，配置事务五项通过。入口与恢复方式见
[Wine 配置说明](WINE.zh-CN.md)。隔离Xwayland混合缩放12项已通过；实体
niri多屏组合尚未验证。
此实体多屏项已由用户移除验收条件。

原生 Wayland 新字段未声明用途时临时原文回退且不学习，收到用途后恢复。
Chromium 150 的延迟用途与首次按键问题已有真实回归；不能发送用途的客户端
会保持保护性回退，优先使用 GTK/Qt 桥接。修复在固定 Fcitx 5.1.21 的用户
前缀 overlay 中，不修改系统包，也不修改浏览器或 Wine 源码。

Discord 的证据只覆盖隔离启动器 Electron 渲染器，未覆盖登录聊天界面，
没有发送聊天。后续未修改真实界面的隔离启动共观察18次，仍只有更新器，
且更新服务无法连接，未取得可用于测试的实际输入框；该诊断不算输入通过。
登录聊天界面已由用户移除验收条件。
云端服务契约经本地 HTTP(S) 测试，尚未配置外部生产服务。
SIGKILL 故障注入不等同于物理断电；没有声称任意软件的全部光标场景和
所有多屏组合已经通过。

## 文件范围

核心与事件接口在 `include/tipe`、`src/tipe_core.cpp`；学习与模型位于
`src/learning.cpp`、`model.cpp`、`local_language_model.cpp`、`correction.cpp`
以及 `cloud_*.cpp`。Fcitx 与绘制位于 `tipe_fcitx.cpp`、`candidate_*.cpp`、
`client_side_candidate_adapter.cpp`、`tipe_ui.cpp`；控制中心在
`control_window.cpp`、`tipe_control.cpp`、`support_page.cpp`。
`integration` 保存固定版本的 GTK/Qt/classicui/Wayland overlay 与构建入口，
`packaging` 保存主题、图标与元数据，`scripts` 提供安装事务、重启、诊断和
桌面夹具，`tests` 保存自动用例与语料，`docs` 保存说明及直接证据。
